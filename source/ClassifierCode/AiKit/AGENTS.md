# Задание: профиль классификатора для объекта

Ты собираешь профиль для плагина Revit «Код по классификатору» (ToadTools). Плагин по профилю записывает в каждый элемент инженерных моделей код и описание позиции классификатора заказчика. Профиль ты собираешь из моделей объекта (выгрузки в `exports\`) и таблицы кодов заказчика (Excel в этой папке). Профиль проверяет координатор и раздаёт проектировщикам, поэтому он должен быть правильным, а спорное — вынесено в отчёт, а не решено молча.

## Что в папке

| Путь | Что это | Можно менять |
|---|---|---|
| `kit\FORMAT.md` | формат профиля и как работает движок — **прочитай первым** | нет |
| `kit\profile.schema.json` | JSON Schema профиля | нет |
| `kit\base.classifier.json` | профиль-основа: правила другого объекта, их и дорабатываешь | нет |
| `kit\filled-by.classifier.json` | профиль, которым модели уже заполнялись (если есть) | нет |
| `kit\check\check.exe` | проверялка: тот же движок, что в Revit | нет |
| `exports\*.export.json` | выгрузки моделей (по файлу на модель), `exports\_журнал.txt` — журнал выгрузки | нет |
| `*.xlsx` | таблица кодов заказчика | нет |
| `profile.classifier.json` | **твой результат** — профиль объекта | да |
| `REVIEW.md`, `ОШИБКИ_В_МОДЕЛЯХ.tsv` | **твой результат** — отчёт координатору и список ошибок в моделях | да |
| `work\` | рабочие файлы проверялки и твои заметки | да |

Проверялку запускай из этой папки: `kit\check\check.exe <команда> …`. Если запуск exe из этой папки запрещён политикой компании, тот же `check.exe` лежит в папке установки плагина: `%AppData%\Autodesk\Revit\Addins\<год>\ToadTools\ClassifierCode\AiKit\check\check.exe` (запускай его, оставаясь в этой папке). Команда без аргументов печатает справку. Опции пишутся `--имя значение` или `--имя=значение`; значение с пробелами — в кавычках; неизвестная опция — ошибка.

**Оболочка.** В PowerShell и cmd пути пишутся как здесь: `kit\check\check.exe … exports\*.export.json`. В bash (Git Bash — оболочка Claude Code на Windows) обратная косая черта съедается — пишите прямые: `kit/check/check.exe run profile.classifier.json "exports/*.export.json"` (маску — в кавычках, её раскрывает сама проверялка).

## Шаги

1. Прочитай `kit\FORMAT.md`.
2. Таблица заказчика: `kit\check\check.exe classifier <файл.xlsx> [--sheet имя|номер] [--prefix 04.05]`. Результат — `work\positions.tsv`. Без `--sheet` берётся первый непустой лист — проверь по первой строке вывода (там список листов), тот ли это: листы с укрупнёнными или бюджетными статьями не подходят, нужен лист с полными кодами инженерных систем. Если Excel не один, лист неочевиден или колонки угадались неправильно — спроси координатора. Если таблица шире инженерных систем, возьми только нужную ветку (`--prefix`) и напиши в отчёте, какую.
3. Обзор моделей: `kit\check\check.exe summary exports\*.export.json`. Читай `work\summary\*.tsv`: `models.tsv` (модели: элементов, категорий, сколько уже с кодом и каким профилем заполнялись), `groups.tsv` (семейство / тип / наименование с количеством), `systems.tsv` (имена и сокращения систем), `worksets.tsv`, `parameters.tsv`, `values.tsv`, `current-codes.tsv`. **Выгрузки целиком не читай** — они огромные; для конкретных элементов есть `explain`.
4. Профиль объекта: скопируй `kit\base.classifier.json` в `profile.classifier.json` и поменяй `id` на новый GUID (PowerShell: `[guid]::NewGuid()`), `name` (объект), `version` (`1.0`), `fileNamePatterns` и `fileTokens` режимов — под имена моделей этого объекта. Если раздел модели по имени файла не определяется, а менять шифры нельзя, задай модель → режим в `work\modes.json`: `{"ИмяМодели": "heating"}` — ключ — имя модели, как в `models.tsv`, значение — `key` режима профиля.
5. Классификатор: `positions` — **только** из `work\positions.tsv` (служебная `999` «Не учитывать» допустима). Разделы (`disciplines`), типы (`types`), таблицы «раздел + тип → код» (`tables`) и замены — под коды заказчика. Знание основы (что манометр — КИП, что изоляция берёт систему трубы, как узнать пожарный шкаф) переиспользуй, не переписывай.
6. Шифры систем, слова в наименованиях, параметры — бери из `summary`, а не по памяти.
7. Цикл до готовности:
   - `kit\check\check.exe validate profile.classifier.json --exports exports\*.export.json --classifier work\positions.tsv` — должно быть «Профиль без ошибок»;
   - `kit\check\check.exe run profile.classifier.json exports\*.export.json` — покрытие, коды с частыми наименованиями, не классифицированные (`work\run\run.md`, `codes.tsv`, `unclassified.tsv`);
   - `kit\check\check.exe explain profile.classifier.json exports\<модель>.export.json <Id или часть наименования>` — почему элемент получил такой код;
   - разбери не классифицированные и подозрительные коды (огнетушитель в арматуре, кран в КИП), поправь профиль, снова `validate` и `run`.
   Остановись, когда оставшиеся без кода объяснимы (задания на отверстия, «Не учитывать», чужие для объекта элементы) или когда дальше нужен ответ координатора.
8. Если в моделях уже стоят коды (`current-codes.tsv` не пуст): `kit\check\check.exe diff profile.classifier.json exports\*.export.json` → `work\diff.tsv`. Строки «правка руками» (код ставили вручную поверх профиля) — лучшие примеры, как надо; разберись и поправь профиль или объясни в отчёте. Если `kit\filled-by.classifier.json` нет, расхождения — только к сведению: не подгоняй под них профиль.
9. Ошибки в моделях: `kit\check\check.exe anomalies profile.classifier.json exports\*.export.json` → `work\anomalies.tsv`. Перенеси подтверждённые в `ОШИБКИ_В_МОДЕЛЯХ.tsv` (ниже).
10. Напиши `REVIEW.md` (формат ниже) и коротко ответь в чате: что готово, что спорно, какие вопросы к координатору.
11. На замечания координатора — правка, `validate`, `run`, обновлённый `REVIEW.md`.

## Правила

- Не выдумывай коды: позиция, которой нет в таблице заказчика, — ошибка.
- Не меняй файлы в `kit\`, `exports\` и Excel.
- `profile.classifier.json` всегда проходит `validate` — иначе это не результат.
- Не читай выгрузки целиком — пользуйся `summary`, `run`, `explain`.
- **Решай по большинству.** Проектировщики ошибаются: элемент не в той системе, не в том рабочем наборе, с чужим шифром. Не добавляй правила и исключения ради единичных выбросов — это ошибки модели, их исправят в модели, и после этого элементы получат правильный код без правки профиля. Выбросы — в «Ошибки в моделях».
- Правило лучше общее (слово, шифр системы), чем по Id или имени конкретного семейства.
- Спорное не решай молча: вынеси в отчёт с вариантами.
- Позиции без элементов в моделях (пусконаладка, ПО, работы) — нормально; перечисли их в отчёте как «в моделях не встречается».

## REVIEW.md

Коротко, по-русски, Markdown. Опирайся на `work\run\run.md`.

```markdown
# Профиль «<название>» <версия>

## Итог
Модели и их разделы; сколько элементов получат код (и сколько ещё получат после добавления параметров из ФОП — «без параметра кода»), сколько нет. Какой лист и ветка таблицы заказчика взяты.

## По кодам
| Код | Описание | Элементов | Частые наименования |
По каждому коду, где есть элементы, 3–5 самых частых наименований — чтобы координатор глазом увидел ошибку.
Позиции без элементов в моделях — одной строкой списком.

## Спорное
Что отнесено по догадке: элементы, решение, варианты.

## Не классифицировано
Группы с причиной: почему это нормально или что нужно от координатора.

## Ошибки в моделях
Сколько и каких (не в той системе, не в том рабочем наборе); подробно — в ОШИБКИ_В_МОДЕЛЯХ.tsv.

## Вопросы координатору
Нумерованный список.
```

## ОШИБКИ_В_МОДЕЛЯХ.tsv

Таблица для проектировщиков (откроется в Excel), разделитель — табуляция, первая строка — заголовок:

```
модель	Id	элемент	сейчас	ожидается	что исправить
```

Только подтверждённые выбросы из `work\anomalies.tsv` и то, что ты нашёл сам (элемент явно не в той системе или рабочем наборе). Id — из выгрузки, по нему проектировщик найдёт элемент в Revit («Выбор по коду»).
